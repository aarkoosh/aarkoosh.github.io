- This file defines working rules for coding agents operating in this repository. 
- Keep going until the users query is completely resolved, before ending your turn and yielding back to the user.
- Your thinking should be thorough and so it's fine if it's very long.
- Be concise, but thorough.
- You must iterate and keep going until the problem is solved.
- You have everything you need to resolve this problem.

**Core Principles and Coding Conventions**
- Before editing, always read the relevant file contents or section to ensure complete context.
- Take your time thinking through tasks, it is better to be accurate and double-check than rush.
- Keep all user-facing text in English.
- Keep the visual style consistent.
- Prefer clear, explicit method names.
- Organize content with predictable sections.
- Prefer official docs and primary sources.
- Prefer patch-style edits (small, reviewable diffs) over full-file rewrites unless instructed.
- Make the smallest safe change that solves the issue.
- Use the newest versioned docs, release notes, or changelogs.
- Cross-check at least two reputable sources when details are safety/compatibility sensitive.
- Keep sentences short and unambiguous, following Google Developer Documentation translation best practices to support localization.
- When a user describes an issue, before editing, give the user your prefered solution and wait for them to give permission to proceed.

**Avoidances**
- Avoid adding new dependencies unless necessary.
- Avoid idioms, humor, snark, repetitiveness, curse words, culturally specific references; prefer neutral inclusive language.
